# 국어 변형 출제실

독서·문학 지문과 선생님 필기를 넣으면 내신 변형 문제를 만들고, 정답을 가린 채 따로 검수한 뒤 걸린 문항을 고쳐 주는 앱.
`prompts/README.md`의 출제 → 검수 → 수정 프롬프트를 자동으로 돌린다.

- 앱: https://claude.ai/artifact/9NWK2wCogbVtCb8M177dYJ (본인만 열 수 있음)
- Claude 호출은 artifact `sample` 기능을 쓴다. 보는 사람의 Claude 사용량을 쓰고, API 키는 필요 없다.

## 공부 모드

세트 화면의 **공부** 탭. 원리와 근거는 `study-science.md`.

- **가림 읽기**: 지문을 2~3문장(시는 3~4행) 구간으로 나눠 하나씩 보여 주고, 가린 뒤 문장 사이 관계를 적게 한다. 끝나면 `sample`(default)이 구간마다 정확/부분/틀림/빈칸으로 판정한다.
- **백지 인출**: 지문을 보지 않고 쓴 글을 지문·해석 자료와 대조한다. 적은 문장(초록 밑줄), 빠진 핵심(빨간 바탕), 잘못 적은 부분을 지문 위에 표시하고 덮은 비율(%)을 남긴다. 다음 인출일은 1·3·7·14일(두 번 연속 90% 이상이면 한 칸 건너뜀). 쓰던 글은 브라우저에 임시 저장.
- **OX 연속 재학습**: OX는 `complex`로 만들고, 정답을 가린 채 `default`로 다시 판단시켜 어긋나거나 애매한 문장은 버린다. 한 번에 오늘 복습할 문장 최대 40개. 틀리거나 "애매해요"를 누르면 3장 뒤에 다시 나오고, 처음 보는 문장은 연속 2번, 복습 문장은 1번 맞히면 통과. 처음에 바로 맞히면 상자가 올라가고(1·3·7·14일 뒤), 아니면 상자 1(다음 날).
- **틀린 문항 → OX**: 문제 풀기에서 채점하면 틀린 객관식의 고른 선지와 정답 선지를 OX에 넣는다(선지별 적절/부적절이 곧 O/X). 틀린 문항마다 원인(지문 내용 / 선지 독해 / 해석 차이 / 시간 부족)과 태도 노트를 남기면 공부 탭에 모인다.
- **오늘 할 복습**(처음 화면): 오늘 OX·백지 인출이 잡힌 지문 목록. 시험일을 넣으면 D-day를 보여 주고, 복습일이 시험 전날을 넘지 않게 당긴다(`settings/main.examDate`).
- 편집 화면의 **공부용으로만 저장**은 문제를 만들지 않고 지문만 저장한다(`stage: 'study'`). 나중에 문제 풀기 탭에서 문제를 만들 수 있다.

데이터: `sets/<id>.study = {read:{at,notes}, recall:[{at,cover,covered,missing,wrong,comment,text}], recallDue, ox:[{id,s,a,refs,why,trap,src,box,due,seen,miss}], causes:[{at,qid,stem,cause,note}]}`

## 자료함과 자동 채우기

**자료함** (목록 화면): PDF를 여러 개 한꺼번에 넣는다. 파일은 이 기기 브라우저의 IndexedDB(`korean-library`)에만 보관하고, 세트에는 골라 넣은 글자만 저장한다.

- pdf.js 3.11.174를 cdnjs에서 필요할 때 불러온다. 워커 스크립트를 먼저 올려 페이지 안에서 돈다 (별도 워커는 CSP 때문에 못 씀).
- 넣을 때 모든 쪽의 글자를 뽑아 둔다. 한글이 거의 없는 쪽은 "글자 없는 쪽"(스캔본)으로 표시한다.
- 종류(교사용 교과서 / 학원 교재 / 문제 / OX 문제)는 파일 이름으로 먼저 짐작하고, 모르면 내용(①·(O)/(X)·지도 관련 낱말 개수)으로 짐작한다. 목록에서 고칠 수 있다.
- 스캔본은 "AI로 읽어 두기"(한 번에 40쪽)로 쪽을 그림으로 그려 `sample`이 옮겨 적게 해야 검색된다.

**알아서 채우기** (편집 화면): 지문 이름이나 첫 구절을 적는다. 지문 칸에 글이 있으면 그 글로 찾는다.

1. 모든 쪽에 점수를 매긴다. 지문이 있으면 띄어쓰기를 뺀 12자 조각이 쪽에 몇 % 나오는지, 없으면 검색어가 몇 번 나오는지.
2. 종류마다 점수 높은 쪽을 고른다 (교사용 교과서는 앞뒤 쪽도, 해설이 이어지므로). 종류별 글자 예산: 교사용 9000, 학원 5000, 문제 3500, OX 2500. 64 KiB를 넘으면 점수 낮은 쪽부터 뺀다.
3. `sample.json`(default)이 제목·종류·지문 본문·해석 발췌·OX·예시 문제를 원문 그대로 골라 온다.
4. 지문은 문장(행)마다 띄어쓰기를 뺀 글자가 PDF 글자에 그대로 있는지 대조해서, 다른 문장을 알려 준다.
5. 해석·OX·예시 칸에는 `──── 자료함에서 가져옴 ────` 아래에 넣는다. 다시 채우면 그 아래만 바뀌고, 위에 직접 쓴 필기는 그대로다.

**직접 쪽 골라 넣기**: 파일·쪽(한 번에 60쪽, 스캔본은 12쪽)·칸을 골라 넣는다.

해석 자료에서 `[출처 쪽]` 머리말이 없는 부분은 선생님 필기로 보고, 필기 → 교사용 교과서 → 학원 교재 순으로 따른다. 분량: 지문·해석·OX는 44,000바이트(한글 약 1만 4천 자), 예시까지 합쳐 62,000바이트. 검수·수정은 한 번에 64 KiB를 넘지 않게 문항을 나눠 부른다.

## 시험지 PDF (굿노트용)

세트 화면의 **PDF로 받기**: A4 2단 시험지. 머리(제목·종류·날짜, 이름·점수 칸) → `[1~N] 다음 글을 읽고 물음에 답하시오.` + 지문(문장 번호 선택) → 문항(〈보기〉 상자, 서술형 답칸 줄) → 선택하면 새 쪽부터 정답표와 선지별 해설(근거 번호).

- pdf-lib 1.17.1(cdnjs) + @pdf-lib/fontkit 1.1.1(jsDelivr)을 누를 때 불러온다. 글자가 벡터라 굿노트에서 확대해도 선명하고 검색된다.
- 글꼴은 발행 파일 `fonts/`에서 받는다: 자주 쓰는 한글 2350자 파일(약 1.5MB)을 먼저 쓰고, 그 밖의 글자가 있으면 전체 글꼴(약 8MB)을 받는다. 전체 글꼴에도 없는 글자(옛한글)는 □로 바꾼다. 글꼴 파일은 `tools/build_fonts.sh`로 다시 만든다 (저장소에는 넣지 않음).
- pdf-lib의 글꼴 부분 추출(`subset:true`)은 이 글꼴에서 글자가 빠져서 쓰지 않는다. 파일이 1MB 남짓 커진다.
- 저장은 `downloads` 기능. 아이폰·아이패드 Claude 앱에서는 공유 메뉴가 떠서 굿노트로 바로 보낼 수 있다.
- 뺀 문항은 싣지 않고 번호를 1부터 다시 붙인다.

## 흐름

1. **출제**: 8문항씩 나눠 부른다 (객관식 최대 40, 서술형 최대 10). 뒤 묶음에는 앞 문항 요약(유형·발문·정답 선지)을 보여 줘서 겹치지 않게 한다. 묶음마다 저장하므로 멈춰도 이어서 만든다.
   지문을 문장(시는 행)으로 나눠 앱이 직접 번호를 붙인다. 원문을 AI가 다시 쓰지 않아서 원문이 바뀌지 않는다. 선지마다 `fits`(적절/부적절)와 근거 번호를 받는다.
2. **검수**: 객관식 정답을 뺀 채 별도 호출로 검토 위원이 직접 푼다. 아래 중 하나라도 걸리면 수정 대상.
   - 검토 위원의 답이 출제 답과 다름
   - 다른 선지도 답이 될 여지가 있다고 함
   - 검토 위원 판정이 통과가 아님
   - OX 정답과 어긋나는 판단 (검토 위원이 확인)
   - 앱 자체 확인: 선지 5개, 발문("적절하지 않은 것" 등)과 `fits` 표시가 맞물려 답이 하나로 정해지는지, 근거 번호가 지문 범위 안인지
3. **수정**: 걸린 문항만 고치거나(출제자가 반박하면 해명을 남김) 새로 만든다.
4. **다시 검수**: 고친 문항만 한 번 더. 그래도 걸리면 `직접 확인`으로 표시하고 남은 지적을 보여 준다.

단계는 세트에 저장해서 멈추거나 창을 닫아도 이어서 할 수 있다. 필기 사진은 저장하지 않는다.

## 데이터 (artifact db)

- `sets/<id>`: `{title, kind, passage, byLine, units: [{t, p}], note, ox, examples, cond: {mc, essay, level, must}, tier, stage, questions, attempts, hadImages, createdAt, doneAt}`
  - `stage`: `new` → `generated` → `reviewed` → `revised` → `done`
  - 문항 `st`: `pending`, `pass`(바로 통과), `flag`(수정 대기), `revised`, `fixed`(고쳐서 통과), `check`(직접 확인)
  - `attempts`: 최근 20번의 풀이 `{at, right, total, answers}`

`index.html`을 고친 뒤에는 같은 주소로 다시 발행한다.
